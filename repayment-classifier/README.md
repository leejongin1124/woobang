# 변제금 상환내역 분류기 (엑셀 매크로)

신용회복위원회 `변제금상환내역조회` 엑셀 1개 → **새출발 파일 + 일반 파일** 2개로 나누고,
분담수수료(3.88%, 원 미만 버림)와 법인계좌 입금 예정액을 계산표에 보여 준다.
인터넷·AI·외부 프로그램을 쓰지 않는다.

## 처음 한 번: 설치 (5분)
1. 이 폴더의 **`변제금분류기.bas`** 를 회사 PC에 받는다. (`src/Repayment.vba` 는 읽기용이라 가져오면 한글이 깨진다)
2. 엑셀에서 **새 통합 문서**를 연다.
3. `Alt + F11` → VBA 편집기 메뉴 **파일 > 파일 가져오기** → `변제금분류기.bas` 선택 → 편집기 닫기
4. `Alt + F8` → **SetupWorkbook** 선택 → 실행 → "설치가 끝났습니다" 확인
5. `F12` → 파일 형식 **Excel 매크로 사용 통합 문서(\*.xlsm)** → `변제금분류기.xlsm` 으로 저장
6. 다음부터는 `변제금분류기.xlsm` 을 열고, 위쪽 노란 줄의 **[콘텐츠 사용]** 을 누른다.

## 매일 하는 일
1. 신용회복위원회에서 `변제금상환내역조회` 엑셀 다운로드
2. `변제금분류기.xlsm` → **[1. 파일 불러오기 / 분류]** → 다운받은 파일 선택
3. 같은 폴더에 `새출발_YYYYMMDD.xlsx`, `일반_YYYYMMDD.xlsx` 생성 (원본 서식 그대로, 건수·No.만 고침)
4. 계산표 **차감입금액** = 법인계좌에 들어와야 할 금액 → 통장 금액을 **통장입금액** 칸에 입력 → 입금차이 0 확인
5. sERP 신용회복수납처리에서 파일마다 [엑셀 업로드] → 총 입금금액에 **원금(합계)** 입력 → 자동점검 → 수납처리 (2번)
6. sERP 처리금액을 **sERP금액** 칸에 입력 → 차이금액 0 확인
7. 중도완제가 있으면 중도완제 줄의 원금(합계)·건수를 직접 입력
8. 필요하면 [계산표 인쇄] → 끝나면 **[초기화]**

## 계산표
| 구분 | 수수료율 | 수수료 | 차감입금액 | 원금(합계) | sERP금액 | 차이금액 | 통장입금액 | 입금차이 | 건수 |
|---|---|---|---|---|---|---|---|---|---|
| 중도완제 | 입력 | 계산 | 계산 | **입력** | 입력 | 계산 | 입력 | 계산 | 입력 |
| 새출발 | 입력 | 계산 | 계산 | 자동 | 입력 | 계산 | 입력 | 계산 | 자동 |
| 일반 | 입력 | 계산 | 계산 | 자동 | 입력 | 계산 | 입력 | 계산 | 자동 |
| 총계 | | 합 | 합 | 합 | 합 | 합 | 합 | 합 | 합 |

- 수수료 = ROUNDDOWN(원금(합계) × 수수료율, 0). 2026-10-30 자료로 신복위 확인서와 같은 값 확인 (4,032 / 23,170).
- 원금(합계) = 상환내역 `합계` 열(원금+이자+기타채무)의 합.
- 분류: `지원구분`에 "새출발"이 들어 있으면 새출발, 나머지는 일반.

## 자동 점검 (불러올 때 알려 줌)
- 원금+이자+기타채무 ≠ 합계인 행
- 처리일자가 여러 날 섞인 경우
- 이미 같은 날짜 결과 파일이 있으면 덮어쓸지 물음
- 결과 파일(`새출발_`, `일반_`)을 원본으로 잘못 고른 경우

## 보안
- 고객 정보는 `변제금분류기.xlsm` 에 저장되지 않는다. 남는 것은 구분별 합계·건수·파일 경로뿐이다.
- 원본과 결과 파일에는 고객 정보가 있으니 sERP 업로드 후 회사 규정대로 보관·삭제한다.
- 시험은 가짜 데이터로만 한다 (`test/make_sample.py`).

## 개발자용
- 고친 뒤 `python3 build.py` 로 `변제금분류기.bas` 를 다시 만든다.
- `test/run_test.sh` : LibreOffice(VBA 호환 모드)로 가짜 데이터 분류·합계·파일 내용을 검사한다.
  LibreOffice에는 양식 단추, 조건부 서식, 파일 선택 창이 없어 이 부분은 **엑셀에서 직접 확인**해야 한다.
